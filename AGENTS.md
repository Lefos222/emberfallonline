- Server-owned character data lives at `heroes.save->'srv'` (Lucky Shots, scrolls, buffs, cosmetics); a trigger blocks client edits and only SECURITY DEFINER RPCs write it via `_write_save`. Why: rewards must not be client-forgeable. Client must flush its save before an RPC and adopt the returned save.
- Lucky Shot odds live in both `ASTRAL_ODDS` (crafting.ts) and `lucky_shot()` SQL; keep them identical.
- Browser reward integration uses typed existing RPCs through `services.ts`, validates response envelopes through `services-contract.ts`, serializes cloud writes before mutation, and adopts returned saves without resaving; this prevents stale drafts from overwriting online rewards.
- Keep pending valuable request UUIDs scoped to character and operation until a validated response succeeds; this makes uncertain Lucky Shot retries safe across refreshes.
- Guild UI reads existing membership tables and invokes existing permission-checked RPCs; client role checks only control presentation and never authorize mutations.
- The Lodge (gathering professions), its guild supply events and its daily commissions were removed, and the Sanctuary placeholder that briefly replaced it is gone as well — the castle has no late-game placeholder building. The legacy `profession_*`, `guild_supply_*` and `daily_profession_*` RPCs and tables still exist server-side — do not re-wire UI to them.
- Scroll effects use a validated `begin_battle` snapshot after serialized save sync; never retry charge consumption automatically, and retain an interruption marker until acknowledged because the existing RPC has no idempotency key.
- Battle reward callbacks accept the confirmed XP multiplier explicitly; non-battle rewards remain unaffected, avoiding global buff state leaking into unrelated rewards.
- Character creation, inventory, profiles and battles use CharacterModel with the shared standalone transparent class/gender assets, never selection-card crops; object-contain preserves proportions and battle effects remain presentation-only.
- CharacterModel owns paired idle/action artwork on equal-size transparent canvases; class-move ancestors select the action pose, while CharacterPose provides presentation-only pose/replay controls without modifying saves.
- Looted and forged armour appearance is derived from the worn chest piece's id (`lookOf`/`gearLook` in `src/game/appearance.ts`), so each drop or craft keeps a stable random variant of the painted class/gender looks in `src/assets/armour/<cls>-<gender>-<look>.webp` (the pool size is read from the shipped art, so new outfits widen future drops); worn Synthesis sets keep their own set art and never take a rolled look — `heroAppearance` picks between the two and every CharacterModel/CharacterPose caller passes both `synth` and `look`.
- Endless encounters derive their roster and circuit difficulty from saved road/wave cursors, not hero snapshots or random UI state; this preserves encounters across refreshes and avoids a fixed Spire difficulty plateau.
- Endless talent branches use the existing talent ranks, point budget and saved Road/Spire high-water marks; their abilities enter buildKit and the shared animation table, so no separate progression or damage engine is introduced.
- Appearance checks run through tests/visual/check_character_appearance.py using isolated in-memory equipment/progression and fixed-size screenshot frames; they never restore sessions or write player saves.
- Building expansions reuse existing material keys, craft/socket/Astral helpers and saved building state; event entry validates the shared UTC opening in an authenticated server function, while encounter rewards retain the existing battle settlement path.
- Dungeon stamina (`src/game/stamina.ts`) is a 200-a-day bar spent 10 at a time by every Dungeon Gate run — boss challenges, elite hunts, expeditions and relic trials — win or lose, charged once on entry by the single `start` in `src/game/Game.tsx` for callers passing `dungeon: true`. Campaign, Conquest, arena and activity battles never spend it. A Stamina Potion (`hero.staminaPotions`, art `src/assets/stamina-potion.png`) is a rare won-dungeon drop (`rollStaminaPotion`) drunk from the HUD bar for +50. Campaign Gate, Conquest Gate and World Tree battles keep their panel mounted under the battle overlay (see `BATTLE_PANELS` in `src/game/Game.tsx`) so the player returns to the screen they fought from.
- Optional saved skill loadouts filter the existing unlocked combat kit at battle entry and always preserve its basic attack; absent loadouts retain legacy kits so progression and old saves remain compatible.
- Diamond prices, gold-pack rates and VIP costs live in `src/game/economy.ts`. The shop's preview test mode (`VITE_PREMIUM_TEST_MODE=1`, fed from `BASE44_PREVIEW_MODE`) spends a save-local `premiumTest` wallet and is intentionally not mirrored in SQL yet; the old `premium_diamonds_vip` RPCs remain authoritative for the server-owned `srv.premium` state. Move these prices into the RPCs when checkout is connected.
- Every gold price a player pays goes through `goldScale`/`scaledGold` in `src/game/gold.ts` (forge recipes, enhancements, gem cuts and fusions, attribute training, barracks upgrade, bag rows, market stock); level 1 must keep legacy prices, and premium diamond/VIP pricing stays out of it because SQL mirrors it.
- Barracks drill ranks live in `src/game/drills.ts` — both the percentage tracks and the attribute tracks (`ATTRIBUTE_DRILLS`, saved in `hero.attrDrills`) reach combat through `computeStats`' shared pipeline (the same path as talents, gems and Astrals), so no second stat engine exists; the Conquest blitz allowance is 3 per Greek day in `src/game/conquest.ts` while floors stay unlimited; the Campaign Gate blitz (`src/game/campaign-blitz.ts`) spends that same allowance and never reaches past a stage the hero has already cleared.
- The Blood Arena (`src/game/Arena.tsx`) lists every public hero and lets any of them be challenged — there is no rating bracket — and the same panel carries the full ladder. A hero gets five duels every twelve hours (`src/game/arena-limits.ts`): the window opens with the first duel and refills twelve hours later (never banked), and a duel is spent on entry win or lose by the single `start` in `src/game/Game.tsx` for callers passing `arena: true`. The arena has no shop and no currency of its own: duels pay gold and rating only, because the arena armory and its Arena Marks were removed.
- Forge recipes (`RECIPES`/`ARMOR_EXTRA` in `src/game/crafting.ts`) and synthesis set totals (`SET_TOTALS` in `src/game/synthesis.ts`) are the armour sink and are tuned deliberately high; raising them is the balance lever for crafted gear, not adding a second cost layer in the UI.
- A blitz is a run of 20 minutes for a shallow climb rising to 50 minutes at `BLITZ_FULL_DEPTH` 100 (`blitzDurationMs` in `src/game/blitz-run.ts`): `campaignBlitz`/`blitz` spend the shared allowance and park the pending rewards on `hero.blitzRun`, every battle entry (the single `start` in `Game.tsx`) is refused while it runs, and the rewards are paid by `settleBlitzRun` when it lands. Finishing early costs 25 Diamonds through the server-owned premium wallet, so it goes through the `skip_blitz` RPC, never the client save.
- Relic Trials (`src/game/relics.ts`, panel `src/game/RelicTrials.tsx`) are the only source of the three class relic collections: every win recovers one piece, undiscovered pieces are favoured, and the piece levels to the hero's current level so a collection keeps pace. Relics are ordinary `Item`s named by their set prefix (`Emberforged`, `Starweave`, `Verdant`), so `progress.setOf`/`setFx` pick them up unchanged; the extra six-piece signature bonuses live in `SET_SIGNATURE`. Saved progress is `hero.relics` (`found` counts and per-rank `clears`). Gear icons are cut from one committed atlas, `src/assets/gear-atlas.jpg` (1920x2144), which stacks two 1920x1072 class sheets: band 0 is the original class gear art and band 1 the relic collection art. An item's band is `Item.art` (absent = 0), falling back to its relic set prefix for saved relics. Ordinary drops and crafts roll either band (`rollArt`) and `iconTier` sweeps each slot's whole icon row across rarities, so every painted weapon, ring, armour, hood/helmet, boot, belt and talisman of both updates is worn in game; relic pieces are pinned to band 1.
- The daily board has two tracks in `src/game/daily-rewards.ts`: the free 30-day board and `VIP_DAILY_REWARDS`, which opens at VIP 3 (`vipBoardUnlocked`, read from `srv.premium.vip`) and keeps its own ledger under `hero.dailyRewards.vip`. The VIP board pays a little more gold and materials, level 1-2 gems and gold chests — never Diamonds and never the rare materials.
- Character creation uses `resetHero` and writes its level to both the save and row; login-time automatic resets remain disabled. Why: fresh characters share one initialization path, while old sessions only update existing rows and cannot restore deleted characters.
- The World Tree (`src/game/worldmap.ts`, panel `src/game/WorldMap.tsx`) is one bounded painted realm: `WORLD_W`/`WORLD_H` size it, `REGION_CONTENT` sets how many sites each painted biome carries, and every raid still pays through the server's `world_raid_complete` node IDs — site names, keeps, ruins and sealed vaults are authored client-side only. Its daily bounty board and vault ledger live in `src/game/worldtree.ts` and the hero's own save (`hero.worldTree`): three bounties rotate each UTC day, progress is counted from confirmed raids only, and a vault's seal is spent once per hero.
- Hero training (`src/game/renown.ts`, panel `src/game/RenownPanel.tsx` inside the Throne Hall's Progression tab) is the battle-earned upgrade track: every *won* fight banks Renown (`renownGain`: 2, +3 boss, +1 dungeon/arena) in `Game.tsx`'s `onEnd`, and Renown buys permanent stat ranks in `hero.renownRanks` (six capped ladders: attack, health, defense, crit, dodge, crit damage). It deliberately uses no gold, no barracks level and no building gate; its bonuses join `computeStats`' shared pipeline like every other track, so no second stat engine exists.
- Farm Mastery (`FARM_MASTERY_BONUS` in `src/game/farm.ts`): at Farm Level 16 every harvest and Bloodoak payout pays 20% more gold and Farm XP. The bonus is applied inside `harvestSlot`/`chargeBloodoak` (and shown in `Farm.tsx` through `withFarmMastery`), so the seed tables stay the base numbers and no second reward path exists.
- The Gold Mine (`src/game/mine.ts`, panel `src/game/GoldMine.tsx`) is the castle building immediately left of the Guild Hall (`BUILDINGS` id `mine`). It banks gold every hour into a cart that holds 24 hours (`minePerHour`, `mineCapacity`), fills while the hero is offline from saved timestamps in `hero.mine`, and whose hourly rate rises with every level up to `MINE_MAX_LEVEL` 40; upgrades are ordinary gold prices through `scaledGold`.
- Guild Wars (`src/game/guild-wars.ts`, panel `src/game/GuildWars.tsx`, SQL `drizzle/migrations/0021_guild_wars.sql` + `0022_guild_wars_v2.sql`) are server-owned: `guild_war_start` / `guild_war_respond` / `guild_war_cancel` / `guild_war_state` / `guild_war_attack` / `guild_war_claim` are SECURITY DEFINER RPCs. A leader or officer declares a CHALLENGE in a bracket from 5v5 to 100v100 (`WAR_SIZES`); the challenged guild's leader or officer accepts or declines it, and accepting freezes both rosters (`guild_war_rosters`, the bracket's strongest members) and opens a 24-hour war. Every roster hero gets TWO attacks for the whole war (`WAR_ATTACKS`), a won attack scores one point, and the higher score takes the larger reward — the loser is still paid, scaled by `warSpoils`/the claim RPC. Only the claim RPC writes the spoils into the save. The client fights the battle and reports `_won`, like every other reward path; until both migrations are applied the panel says so instead of failing silently. The Guild Hall stays mounted under a war battle (`BATTLE_PANELS` includes `guild`).
- The Conquest Gate deals only in Conquest Tokens (`src/game/conquest.ts`): `floorTokens` carries the 20% `CONQUEST_TOKEN_BONUS` bump and gems are bought with `gemTokenPrice` through `buyConquestGem` — there is no gold price for a conquest purchase. The one gold purchase that touches the gate is the Conquest Key (`CONQUEST_KEY_GOLD`, bought through `buyConquestKey` in the Auction House shop): for the rest of the Greek day `conquestRewardMultiplier` doubles every conquest floor and conquest-blitz payout, and `hero.conquest.keyDay` records the day it covers. Campaign, Dungeon and Conquest gates are tabbed panels (`GameTabs`); keep fights and their stamina/blitz behaviour unchanged when editing their layout.
- The hero's weapon is painted into the armour and synthesis art: there is no separate weapon overlay, and `heroAppearance` returns only `synth`/`look`, which every CharacterModel/CharacterPose caller passes on. The earlier experiment where the worn weapon drew its own sword, staff or bow was removed (and its `src/assets/weapons` art with it) — armour alone decides the whole look, sword included.
- The game is played in English, Greek or Polish (`src/game/i18n.ts`), chosen by hand with `LanguagePicker` on the sign-in gate, the hero picker and Settings. The dictionary is keyed by the English source phrase, so an untranslated string simply stays English; `Panel` translates its own title and subtitle, which keeps every window's frame in the player's language. The choice is per device (`localStorage` key `emberfall.lang`) and is never guessed from the browser.
- Every screen draws its own copy through `t()`/`tr()`, looked up in three dictionaries: `TRANSLATIONS` (shared chrome) in `src/game/i18n.ts`, `UI_TEXT` (panel sentences) in `src/game/ui-i18n.ts`, and `CONTENT` (world nouns) in `src/game/content-i18n.ts`. Screens translate at render time with the module-level `t`/`tr` (components re-render because `Game` subscribes through `useT()`); `tr` is the same function under a second name for files holding a local `t` such as `(t) => …` loop variables. Reward lines, combat-log events and status labels are translated where they are produced (`Game.tsx`, `combat.ts`), so a line keeps the language it was written in. `src/test/i18n-greek-polish.test.tsx` fails when any phrase handed to `t()` has no Greek or Polish row, and renders a panel in both languages — keep that test green instead of adding an allowlist entry, which is only for words that genuinely read the same in every language.
- Game content lives beside the interface wording in `src/game/content-i18n.ts` (materials, gems, rarities, skills, astrals, enemies, drills, titles, quests, world-map names). Content dictionaries are wrapped at definition with `locAll`/`locValues`/`locList` from `i18n.ts`, which turns their text fields into language-aware getters, so every existing `MATS[k].name` or `TITLES[i].desc` reads in the player's language without a second lookup at the render site — never wrap those again in the UI. Stored gear names are not data fields: render them through `itemName()` (or `useItemName()`), which translates the "<prefix> <noun> <suffix>" parts and rejoins them in the language's word order; `tName()`/`useTName()` do the same word-group translation for composed names such as gems, astrals and creatures. Keep ids, comparisons and save fields in English — only display text is localised.
- Castle building names are drawn on the building itself: `CastleMap` in `src/game/Game.tsx` measures each label and stacks it clear of its neighbours whenever the language, hover card, map size or fonts change, so longer Greek or Polish names still never overlap. `.castle-map` keeps `flex: none` — without it the flex row shrinks the castle to the viewport width and the names collide.
