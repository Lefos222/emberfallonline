- Admin pages read and change moderation data only through admin-checked SECURITY DEFINER RPCs (`admin_moderation`, `admin_players`, `admin_ban_user`/`admin_unban_user`, `admin_restore_quarantine`, `has_role` on `user_roles`); never gate admin data in the client. Manual bans live in `account_bans` and are enforced in the database (restrictive RLS on heroes/chat plus a hero write trigger); character creation IPs live in the private `hero_origins` table. Why: roles and bans must be server-verified and IPs never publicly readable.
- `/` is the public official site (showcase + sign-in/Play); the game itself lives at `/play`, and sign-in returns there. Why: visitors see the game before entering the castle.
- `/astrion` is the Astrion Entertainment studio site; its catalogue is `src/astrion/games.ts` (add a game there). Why: one data file grows the catalogue.
- Every Astrion game route shows `AstrionIntro` (src/astrion/Intro.tsx) once per browser session; its sound is synthesised with Web Audio so no file is needed. `AstrionBadge` in __root marks every other page.
